# net-tools

[![License: MIT OR Apache-2.0](https://img.shields.io/badge/License-MIT%20OR%20Apache--2.0-blue.svg)](#license)

Cross-platform desktop network diagnostics for Windows, macOS and Linux, built
with Rust and egui. Each tool lives in its own tab, and concurrent probes run
independently.

## Disclaimer

Use this tool only on networks you own or are explicitly authorized to test.

## Features

| Tab | Highlights |
|-----|------------|
| Overview | Interfaces, addresses, gateways, DNS and routes; live RX/TX charts; public IPv4/IPv6 egress with location, ASN and ISP. |
| Ping | Continuous ICMP/UDP/TCP ping with live chart and RTT histogram, loss, min/avg/max, standard deviation and P50/P95/P99 percentiles; independent Path MTU discovery over IPv4/IPv6. |
| MTR | Parallel hop-by-hop probing over ICMP, UDP or TCP with continuous refresh and multiple responders per hop. |
| HTTP Ping | Multi-method requests with DNS, connect, TLS, TTFB and total timings, plus total-time percentiles and histogram. |
| TLS | Batch certificate and chain inspection, SAN, key details, expiry warnings, TLS/ALPN support, revocation (OCSP/CRL), HSTS, CT and CAA checks. |
| Port Scan | TCP connect, SYN half-open and UDP scans, with banner grabbing, live progress and immediate cancellation. |
| Connections | Local TCP/UDP socket inventory with process/PID, state and remote endpoint, filters, process termination and best-effort connection close. |
| IP Insight | Parallel IP geolocation queries across multiple providers. |
| Lookup | RDAP domain/IP lookup with JSON tree, parsed contacts and parent-domain fallback. |
| DNS | dig-like queries, custom server with Google/Cloudflare/OpenDNS/Quad9 IPv4 and IPv6 presets, UDP with TCP fallback, and iterative trace from the root servers. |
| NTP | SNTP query, live analog clock, local/UTC time in milliseconds, server metrics, presets and optional system clock update. |
| Utils | Subnet/CIDR calculator, Wake-on-LAN, IANA port/protocol reference, MAC vendor lookup and timestamp/timezone conversion. |
| Speedtest | LibreSpeed, iperf3 client and built-in iperf3 server; live throughput, RTT/jitter and TCP/UDP metrics. |
| NAT | STUN-based NAT type detection over UDP/IPv4/IPv6 with RFC 5780 behavior discovery, RFC 3489 classic classification, step log and practical explanations for P2P, hole punching, port mapping and relay needs. |

Continuous probes support **Start / Pause / Stop**; one-shot tools and servers
use **Start / Stop**. Pressing **Enter** in a target field restarts the task with
the new target.

The bottom bar provides **Check update** and **Auto check**. Update checks read a
small manifest from the latest GitHub Release and open the release page for the
user to choose the right package. Automatic checks run at most once per day and
can be disabled; a specific version can be skipped.

### Connections viewer

The Connections tab provides a local, netstat/ss-style view of the host:

- Lists TCP and UDP listening sockets, bound ports and active connections with
  local/remote endpoints, normalized TCP state, PID, process name and owner UID
  when the operating system exposes them.
- Filters by process name or PID, local port, remote address/port, protocol and
  connection state.
- Supports automatic refresh with an adjustable interval, manual refresh, and
  copy/CSV/JSON/HTML export of the visible rows.
- Selecting a row allows ending the owning process, with an optional forced
  termination confirmation, or closing the connection on a best-effort basis.

Process names and destructive actions require appropriate privileges. Closing a
connection is platform-dependent: Linux uses `ss -K` (root and kernel
`SOCK_DESTROY` support required), Windows supports IPv4 TCP only, and macOS
cannot close another process's socket, so end the process instead.

TCP Ping uses a normal TCP connect (SYN) and therefore works on hosts that drop
ICMP, without elevation; it does not report a reply TTL. The TCP destination port
accepts common presets and remembers recent custom values. TCP Traceroute captures
the routers' ICMP errors and needs a raw socket. On Windows, UDP MTR, TCP MTR and
Path MTU request administrator rights through a confirmation dialog followed by
the system UAC prompt.

Path MTU sends ICMP echo probes with the Don't Fragment bit (IPv6 disables local
fragmentation) and binary-searches the largest passing MTU. It is independent from
the continuous ping, and the IPv6 result is an estimate that does not account for
extension headers.

TLS targets accept one entry per line or comma-separated values in the form
`host`, `host:port`, `[IPv6]:port` or an HTTPS URL. The TLS tab sends a TLS
handshake and reads certificate details; the optional revocation, HSTS, CT and
CAA checks add OCSP/CRL downloads, a single `HEAD /` request and DNS lookups.
Concurrency is capped at ten targets. TLS uses the rustls `ring` provider, so
post-quantum hybrid key-exchange groups are not offered; TLS 1.2/1.3 and the
standard cipher suites are unaffected.

The Utils port reference is generated from the IANA service-name and port-number
registry, which IANA and IETF dedicate to the public domain under CC0 1.0. The
MAC vendor tool first checks a bundled snapshot of common IEEE registration
authority prefixes; when enabled, a local miss may be queried against
[MACLookup.app](https://maclookup.app), sending only the six-digit OUI prefix.
See the [MACLookup.app terms](https://maclookup.app/terms-and-conditions) and
the source notes in the generated data files.

NAT detection uses public STUN servers over UDP and is available for IPv4 and
IPv6. RFC 5780 reports mapping and filtering behavior and derives a user-facing
NAT type; RFC 3489 is kept for comparison and is marked obsolete. Public STUN
servers may be offline or may not support the `CHANGE-REQUEST` extension, so try
another server when the result is unsupported. STUN only observes the outermost
mapping and cannot prove the presence of carrier-grade NAT or double NAT on its
own. Use this tool only on networks you own or are authorized to test.

## Download and run

Download the package for your platform from
[GitHub Releases](https://github.com/playhard-pro/net-tools/releases). No Rust
toolchain is required.

### Which file?

| OS | Architecture | File |
|----|--------------|------|
| Linux | x86_64 / amd64 | `net-tools_<version>_linux_amd64.deb` or `.AppImage` |
| Linux | arm64 / aarch64 | `net-tools_<version>_linux_arm64.deb` or `.AppImage` |
| Windows | x64 | `net-tools_<version>_windows_x64.zip` |
| Windows | arm64 | `net-tools_<version>_windows_arm64.zip` |
| macOS | Apple Silicon (arm64) | `net-tools_<version>_macos_aarch64.dmg` |
| macOS | Intel (x86_64) | `net-tools_<version>_macos_x86_64.dmg` |

`<version>` is the release version, for example `0.3.4`. Check your architecture
with `uname -m` on Linux/macOS (`x86_64`, `aarch64` or `arm64`), or under
*Settings → System → About → System type* on Windows.

### Linux

**deb** installs system-wide and registers with the package manager:

```bash
sudo apt install ./net-tools_<version>_linux_amd64.deb
```

If dependencies are missing, run `sudo dpkg -i <package>` followed by
`sudo apt-get -f install`. The package declares only the base C runtime; GUI
libraries may be needed (see
[Linux runtime dependencies](#linux-runtime-dependencies)).

**AppImage** is portable and needs no installation:

```bash
chmod +x net-tools_<version>_linux_amd64.AppImage
./net-tools_<version>_linux_amd64.AppImage
```

If FUSE is unavailable, install `libfuse2` or append
`--appimage-extract-and-run`.

### Windows

Extract the zip and run `net-tools.exe`. Raw-socket probes request administrator
rights through UAC, so the app can also be started normally. SmartScreen may warn
because the archive is not code-signed; choose *More info → Run anyway* if you
trust the source.

### macOS

Open the dmg, drag `net-tools.app` into *Applications*, then launch it. Releases
are signed and notarized when the Apple secrets are configured; otherwise the
app is ad-hoc signed and macOS asks for confirmation under
*System Settings → Privacy & Security → Open Anyway*. If an older build reports
that the app **is damaged**, clear the quarantine attribute:

```bash
sudo xattr -dr com.apple.quarantine /Applications/net-tools.app
```

Raw-socket probes require `sudo` (see
[Privileges](#privileges-unprivileged-best-effort)).

### First run

Features start unprivileged except raw-socket probes. On Windows, probes that need
a raw socket show an explanation dialog and then request UAC. On other platforms,
the status bar reports any missing capability, and `copy cmd` offers the matching
authorization command.

## Build and run

Requires stable Rust ([rustup](https://rustup.rs)):

```bash
cargo run --release -p net-tools
```

### Linux runtime dependencies

Install X11/Wayland and OpenGL client libraries, for example on Debian/Ubuntu:

```bash
sudo apt-get install -y libxkbcommon0 libxkbcommon-x11-0 libxcursor1 libxi6 \
  libxrandr2 libxfixes3 libxinerama1 libwayland-client0 libgl1 libegl1 xkb-data
```

Windows and macOS need no extra libraries.

## Privileges (unprivileged, best effort)

Raw-socket features either request elevation or show a clear message when
permissions are missing:

| Platform | Available unprivileged | Requires privileges |
|----------|------------------------|---------------------|
| Linux | ICMP ping (ping socket), UDP ping, TCP ping, Path MTU (ping socket), TCP connect scan | ICMP MTR, TCP MTR, SYN scan, UDP MTR |
| macOS | UDP ping, TCP ping, TCP connect scan | ICMP, MTR, TCP MTR, Path MTU, SYN |
| Windows | ICMP ping (system API), UDP ping, TCP ping | TCP MTR, Path MTU, SYN scan, UDP MTR |

### Granting privileges

- **Linux**: grant only the required capabilities instead of running as root:

  ```bash
  sudo setcap cap_net_raw,cap_sys_time+ep "$(readlink -f "$(which net-tools)")"
  ```

  `cap_sys_time` is only needed by NTP **Set time**; network probes need
  `cap_net_raw`. Alternatively run `sudo ./net-tools`.
- **macOS**: `sudo ./net-tools`.
- **Windows**: no manual elevation is required. Starting UDP MTR, TCP MTR or
  Path MTU shows a short explanation and then requests UAC; cancelling the prompt
  is reported without stopping the UI. Running the app as administrator remains
  available for environments that prefer it.

The status bar tracks probing and raw-socket capabilities separately and only
shows permission hints for real permission errors.

## Packaging

Linux and macOS packages use
[cargo-packager](https://github.com/crabnebula-dev/cargo-packager). Windows uses
a zip so the executable can run elevated. Artifacts are written to `dist/`, and
each architecture is packaged on a native runner.

```bash
cargo install cargo-packager --locked
cargo build --release

# Linux (x86_64 and arm64)
cargo packager -c packager.toml -f deb,appimage   # needs patchelf squashfs-tools file
# macOS (Apple Silicon and Intel, run on the matching architecture)
bash scripts/package_macos.sh
# Windows (x86_64 and arm64)
pwsh scripts/package_windows.ps1 -Arch x64
pwsh scripts/package_windows.ps1 -Arch arm64
```

The macOS script creates the dmg from the verified app after signing.

### Application icon

The master icon is `assets/icon.png`. After replacing it:

```bash
cp new-icon.png assets/icon.png
python3 scripts/generate_icons.py   # writes assets/icon.ico
cargo build --release
cargo packager -c packager.toml -f deb,appimage
bash scripts/package_macos.sh
```

The PNG is used at runtime and by Linux/macOS packaging; the ICO is embedded in
the Windows executable by `crates/app/build.rs`.

## Cross-compilation

Cross-compilation builds only the executable. Packages still require native
tooling, so releases are built on native CI runners.

### Windows (MSVC, recommended)

```bash
sudo apt-get install -y clang lld llvm cmake ninja-build
rustup target add x86_64-pc-windows-msvc
cargo install cargo-xwin --locked

cargo xwin build --release --target x86_64-pc-windows-msvc -p net-tools
```

`cargo xwin` downloads the MSVC CRT and Windows SDK automatically. Use
`--xwin-version`, `--xwin-sdk-version` or `--xwin-crt-version` to pin versions.

### Windows (GNU)

```bash
sudo apt-get install -y mingw-w64
rustup target add x86_64-pc-windows-gnu
cargo build --release --target x86_64-pc-windows-gnu -p net-tools
```

If the linker is not detected, set
`CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER` and
`CARGO_TARGET_X86_64_PC_WINDOWS_GNU_AR` to the MinGW tools.

### macOS

Building from Linux needs the Apple SDK and
[osxcross](https://github.com/tpoechtrager/osxcross); building on a Mac or CI is
usually simpler:

```bash
rustup target add aarch64-apple-darwin x86_64-apple-darwin
cargo build --release --target aarch64-apple-darwin -p net-tools
cargo build --release --target x86_64-apple-darwin -p net-tools
```

### Notes

- `rustls` uses the C-based `aws-lc-rs` backend by default. If cross-compiling it
  fails, install `cmake`, `ninja` and a target C compiler, or switch to `ring`.
- `cargo packager` only produces packages for the host platform.

## CI and releases

- `.github/workflows/ci.yml`: build, tests, clippy (warnings are errors) and
  formatting checks on Linux, Windows, macOS Intel and macOS Apple Silicon.
- `.github/workflows/release.yml`: on a `v*` tag, build and package Linux
  (.deb/.AppImage), Windows (.zip) and macOS (.dmg for Apple Silicon and Intel)
  artifacts, then publish one GitHub Release. `release.toml` controls whether
  that release is a testing pre-release or a normal stable release.
- `.github/workflows/promote-release.yml`: manually promote a tested pre-release
  to the latest stable release without rebuilding it.

### macOS signing and notarization

Set these repository secrets to sign and notarize macOS builds. Without them,
builds are ad-hoc signed and require manual first-launch approval.

| Secret | Purpose |
|--------|---------|
| `APPLE_SIGNING_IDENTITY` | `Developer ID Application: ...` identity |
| `APPLE_CERTIFICATE` | Base64 encoded Developer ID `.p12` |
| `APPLE_CERTIFICATE_PASSWORD` | `.p12` password |
| `APPLE_ID` | Apple ID for `notarytool` |
| `APPLE_PASSWORD` | App-specific password |
| `APPLE_TEAM_ID` | Apple Developer team ID |
| `APPLE_KEYCHAIN_PROFILE` | Optional alternative to the Apple ID trio |

The same variables work locally:

```bash
APPLE_SIGNING_IDENTITY="Developer ID Application: ..." \
    bash scripts/package_macos.sh
```

### Cutting a release

Every release is first published as a pre-release for local testing:

```bash
# release.toml must contain: channel = "testing"
scripts/bump_version.sh 0.2.6   # Cargo.toml, packager.toml, Cargo.lock
git commit -am "Bump version to 0.2.6"
git tag v0.2.6
git push origin main v0.2.6
```

The release workflow builds every platform, creates a GitHub pre-release and
attaches `update.json`. The in-app updater keeps pointing at the previous stable
release during this phase.

After the packages have been tested, promote the same build:

```bash
# Set channel = "stable" in release.toml, then commit and push it.
# Run the Promote Release workflow with the tested tag, for example v0.2.6.
```

Promotion only clears the pre-release flag and makes that release the latest, so
users receive exactly the build that was tested. The release workflow rejects a
tag that does not match the workspace version. Remember to set `release.toml`
back to `channel = "testing"` before starting the next release cycle.

The workspace `Cargo.toml` is the version source; member crates inherit it.

## Project layout

```
crates/core    # probing engines and config models (no UI)
crates/app     # egui desktop application
locales/       # i18n files (en / zh-CN)
assets/        # icons and bundled font
scripts/       # icon, packaging and version helpers
screenshots/   # README screenshots
packager.toml  # cargo-packager configuration
.github/       # CI and release workflows
```

## Testing

```bash
cargo test --workspace
```

Probe engines have loopback-based integration tests. Tests that need raw sockets
are skipped when privileges are unavailable.

Dependency, license and advisory checks use
[cargo-deny](https://embarkstudios.github.io/cargo-deny/) (`deny.toml`):

```bash
cargo install cargo-deny --locked
cargo deny check
```
